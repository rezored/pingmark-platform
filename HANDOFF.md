# Pingmark: състояние на проекта и следващи стъпки

*Последно обновяване: 1 ноември 2026 · клон `feat/mcp-server-and-privacy`*

## Накратко

Протоколът `!@` вече има три работещи клиента:

1. **Chrome разширение (v0.4.0).** Пишеш `!@`, потвърждаваш и получаваш линк с локацията. Поправени са сериозни проблеми с поверителността.
2. **SDK (`@pingmark/sdk` v0.2.0).** Разпознава всички форми на pingmark, нивата на точност (`!@~`, `!@~~`) и смята разстояния.
3. **MCP сървър (`@pingmark/mcp-server` v0.1.0).** ИИ асистенти (Claude Code, Claude Desktop, Cursor) разбират `!@`, искат локация със съгласие и намират места наблизо, включително кое е отворено в момента.

И двата npm пакета са **подготвени, но не са публикувани** (виж „Публикуване в npm“).

---

## Настройка на нов компютър

```bash
git clone https://github.com/rezored/pingmark-platform.git
cd pingmark-platform
git checkout feat/mcp-server-and-privacy

npm install
npm run build        # SDK → MCP сървър → Chrome разширение
npm test             # 17 теста + 2 онлайн (PINGMARK_TEST_ONLINE=1 npm test)
```

Изисква Node.js 18+ (тествано с 22).

**MCP сървърът в Claude Code** (настройката е локална за всяка машина и не се пренася):

```bash
claude mcp add pingmark -- node <пълен-път>/pingmark-platform/packages/mcp-server/dist/index.js
```

След публикуване в npm ще е достатъчно `claude mcp add pingmark -- npx -y @pingmark/mcp-server`.

**Chrome разширението:** `chrome://extensions` → Developer mode → Load unpacked → папка `extensions/chrome`.

## Какво е направено

### Chrome разширение (`extensions/chrome`)

| Проблем | Решение |
|---|---|
| Работеше в полета за парола, email и номер | Работи само в textarea, text, search и rich-text. Пропуска и `autocomplete` за пароли, OTP и карти |
| `Pass!@#` и `hey!@john` задействаха споделяне | `!@` трябва да е отделна дума. Ако пишеш след него, се отказва |
| Локацията се вземаше без питане | Prompt „📍 Share your location here?“. Tab или клик потвърждава, Esc отказва |
| Сайтът получаваше постоянно право за геолокация | Локацията се чете от offscreen документ на разширението (`src/offscreen.ts`) |
| Линкът се вмъкваше на произволно място | Позицията на `!@` се запомня и проверява |
| Preview картата влизаше в текста на съобщението | Линкове в редактори се пропускат |
| Чупеше React редактори | `execCommand('insertText')` с резервен вариант |

Махнати са ненужните права (`<all_urls>`, `activeTab`). Изисква Chrome 116+.
⚠️ **Не е тествано в истински Chrome.** Провери `Arrived !@` + Tab, `Pass!@#`, поле за парола, Gmail и WhatsApp Web.

### SDK (`packages/sdk`)

Само добавено, нищо съществуващо не е променено:
- `extractMentions(text)` намира `!@lat,lon`, `!@~`, `!@~~`, „голо“ `!@`, pingmark линкове и `geo:` URI.
- `coarsen()`, `formatToken()` за нивата на точност: exact ~1 м, street ~100 м, area ~1 км, city ~10 км.
- `distanceMeters()`, `bearingDegrees()`, `compassDirection()`.

### MCP сървър (`packages/mcp-server`)

| Инструмент | Какво прави |
|---|---|
| `request_location` | Отваря страница на 127.0.0.1. Човекът вижда причината, избира точност и споделя. Координатите се закръглят в браузъра |
| `parse_pingmarks` | Намира всички места в текст |
| `describe_location` | Описва място с думи, никога по-точно от споделената точност |
| `find_nearby` | Места наблизо с `open_now` / `closes_at` по местно време (и празници). Радиусът се разширява сам, а `only_open` оставя само отворените |
| `distance` | Разстояние, посока и време пеша |
| `format_pingmark` | Токен и линкове |

Данните идват от OpenStreetMap: Nominatim, а Overpass с предпазител. Тествано с реален сценарий: „отворена аптека, `!@~`“ от района на Горна Оряховица.

## Публикуване в npm (ти трябва да го направиш)

1. Създай npm акаунт и **организация `pingmark`** на npmjs.com (безплатно за публични пакети). Без нея `@pingmark/...` не може да се публикува.
2. Логни се и публикувай:
   ```bash
   npm login
   npm publish -w @pingmark/sdk          # първо SDK
   npm publish -w @pingmark/mcp-server   # prepublishOnly пуска typecheck, build и тестове
   ```
3. Провери: `npx -y @pingmark/mcp-server` трябва да стартира и да изпише `ready on stdio`.
4. **Официален MCP регистър:** в `package.json` вече има `"mcpName": "io.github.rezored/pingmark"`. Инсталирай `mcp-publisher`, пусни `mcp-publisher init` (генерира `server.json`), после `mcp-publisher login github` и `mcp-publisher publish`. Сравни стъпките с актуалната документация на registry.modelcontextprotocol.io, защото форматът се променя.

Съдържанието на пакетите е проверено с `npm pack --dry-run`. SDK: 7 файла, 5,4 kB. MCP: 4 файла, 16,4 kB (SDK-то е вградено в bundle-а).

## Известни проблеми

1. **Публичният Overpass често е претоварен** и изрично иска автоматизираните потребители да имат собствена инстанция. Резервният вариант (Nominatim) намира по-малко места. За продукция трябват собствени Nominatim и Overpass (`PINGMARK_NOMINATIM_URL`, `PINGMARK_OVERPASS_URL`).
2. **Покритието на OSM в малките населени места е слабо.** Това е аргумент за Place Cards (виж по-долу).
3. **Спецификацията и кодът се разминават.** Спецификацията ползва `pingmark.me`, кодът `map.pingmark.me`. Форматът на timestamp е различен на трите места. Нивата `!@~` / `!@~~` ги няма в спецификацията. Нивото „street“ няма маркер: SDK-то го извежда от броя десетични знаци (3 → street, 4+ → exact), което също трябва да влезе в спецификацията. Всичко това трябва да се оправи в спецификация v0.3.
4. **`landing/vendor/sdk` и `map/vendor/sdk` са стари ръчни копия** на SDK-то.
5. **`extensions/chrome/content.js`** е стара версия, която manifest-ът не ползва. Може да се изтрие.
6. **`README.md` в корена е в UTF-16.** Добре е да се конвертира в UTF-8.
7. **`opening_hours` е с LGPL-3.0.** Ползва се като непроменена зависимост, което е позволено и в платен продукт.

## Стратегия (обобщение на решенията)

**Модел:** синтаксисът `!@` е безплатен и отворен („заветът“), а платените са resolver-ите и услугите. Аналогията е Git срещу GitHub.

**Ключов принцип:** спецификацията трябва да е **неутрална към resolver-а**. Ако задължава `pingmark.me`, никоя платформа и никой орган по стандартизация няма да я приеме. `pingmark.me` печели, като е подразбиращият се и най-добрият resolver.

**Какво реално може да се продава:**
1. Live локация с E2E криптиране (`!@live:30m`). Сървърът не вижда локацията.
2. B2B „Pingmark for Teams“: одитна следа за присъствие (куриери, техници, охрана).
3. White-label resolver на домейна на клиента.
4. API за платформи: preview, геокодиране, собствена OSM инфраструктура.
5. По-късно: именувани места (`!@pizza-roma`).

**Тезата за ИИ:** търсенето се мести от Google към LLM-ите, а най-ценната реклама винаги е била локалната. LLM-ите са „слепи“ за мястото. Pingmark може да е **отвореният слой за съгласие за локация пред ИИ** и **източникът на проверени локални данни** (Place Cards: машинно четими карти на бизнеси, „llms.txt за места“). Pingmark не трябва да е рекламна мрежа.

**Защита:** патент не е възможен (публикацията в arXiv е предшестващо състояние на техниката, а EPO няма гратисен период). **Регистрирай търговската марка „Pingmark“.**

**MiroFish:** решихме „не сега“. Симулирани агенти не заместват реални потребители, AGPL-3.0 противоречи на платения модел, а и е скъпо.
